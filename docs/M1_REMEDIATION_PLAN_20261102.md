# M1 Motion Prior 联合训练修复建议

依据：[2026-11-02 静态审计](M1_STATIC_AUDIT_20261102.md)。本文是待实施方案，不代表已修复或已完成物理验证；本次提交不启动训练。

## 1. 推荐路线

保留 Prior 规划、Actor 跟踪、WM 提供梯度的分工，先消除输入与控制契约问题，再依次验证跟踪、动力学梯度和联合优化。暂时不以增加网络规模、延长训练或降低解冻门槛作为主要措施。

| 阶段 | 具体交付 | 进入下一阶段的依据 |
|---|---|---|
| A：接口与数据修复 | 归一化 v2、统一工作姿态与动作范围、命令响应检查 | 微小状态扰动不造成轨迹方向突变；目标与控制范围相容 |
| B：可信参考跟踪 | 固定参考集合、分任务跟踪指标、速度/TCP 跟踪项 | 可达参考上的实际跟踪与任务指标共同改善 |
| C：WM 验证 | 独立真实验证集、任务相关多步误差、局部动作方向检查 | WM 预测的局部改进能在真实动力学中复现 |
| D：Prior 后训练 | 参考与执行双重目标、统一损失尺度、受限更新 | 参考质量、可跟踪性和真实任务效果共同改善 |
| E：混合任务 | 固定 1024/1024 环境分组，Replay 分层采样 | L/M 分别达标，任一任务不被平均结果掩盖 |

这些门槛应按任务容差和实际验证数据确定数值，不能用本次合成状态反例直接指定一个通用阈值。

## 2. 先解决第六关节的归一化问题

推荐保留真实 q6/qd6 输入，并在预训练中加入合理的状态变化和对应的可执行未来。归一化按物理量分组：角度、角速度、线速度等分别设置有意义的最小尺度，不能让“几乎没有数据方差”变成“该维度对网络无限重要”。具体下限应根据传感器噪声、跟踪误差和实际状态范围选取。

实施要点：

1. 将 normalization、特征约定和机器人指纹一起版本化，保留旧 checkpoint 作为可复现基线。
2. 对理论上恒零的 latest-heading 分量，在数学上确认后使用一致的解析表达，避免不同实现的舍入误差被放大。不能据此把物理上可动的 q6 也直接清零。
3. 重新校准或训练网络。直接替换旧 std 会改变输入分布；即便重参数化第一层以保持旧函数不变，也会保留旧函数的异常敏感性，不能视为问题解决。
4. 扰动数据时应保证历史的 q/qd 和未来运动一致，避免简单加独立噪声导致时序自相矛盾。传感器噪声增强与真实姿态扰动应分开处理。
5. 记录标准化输入的分位数、最大值、超出训练支持范围的比例，以及分任务命令响应。异常输入处理和回退动作需通过物理验证，不能默认零动作在所有姿态下都安全。

离线验收包括同一历史下的前进/停止/后退命令，以及 q6、qd6、root 速度和姿态的小扰动网格。要求响应方向与命令相容、变化连续；停止命令允许合理制动过程，不要求所有预测位移瞬间归零。

如果产品确实不需要第六轴，可另行设计固定轴实验，但必须同步处理控制、观测和数据；不建议只在 Prior 输入端隐藏它。

## 3. 统一工作姿态、动作范围与数据意图

首先确定机械臂的常用工作区：若采用当前折叠初始姿态，数据应包含从该姿态部署到工作姿态的过程；若采用数据中的展开姿态，必须先验证其支撑稳定性、碰撞和控制能力。不能仅为降低 tracking loss 而直接更换 reset 姿态。

近期优先保持一个清晰的、经验证的位置目标映射，重新标定每个关节的工作范围，并对数据目标做覆盖审计。更长远可尝试 reference 加有界残差：

`q_target = q_reference + bounded_residual`

`wheel_rate_target = wheel_rate_reference + bounded_residual`

这种映射更符合跟踪任务，但前提是 reference 已可靠。它也让 Prior 对动作有更直接的影响，因此必须有目标限位、速率约束和分布外检测；硬裁剪区域的梯度消失不能忽略。它应作为独立控制接口版本和对照实验，不与其他修复同时混入。

数据方面建议：

- L：根据目标命令生成启动、停止、换向、偏差恢复，而不是只保留“当前速度等于目标”的窗口。补充轮子滚动推进的明确样本，并区分滚动、迈步与混合行为。
- M：从实际初始工作区采样可达目标，保留 Reach 与 Hold 的语义；明确是否允许底盘协同移动。机械臂任务若将来涉及抓取/受力，还需要额外对象与接触状态，当前 TCP Reach 不等于完整 manipulation。
- M 的零轮速不能继续作为无有效监督的占位值使用。若任务意图为固定底盘，应提供经验证的轮速/接触约束或单独的任务正则；不能要求 Actor 无条件相信没有监督支持的轮速输出。
- 用受控物理跟踪收集可执行轨迹来修正运动学 bank，保留原始轨迹及其可行性标签；不能仅凭 FK/FCL 通过筛选动力学数据。

## 4. 明确优化参考轨迹与执行轨迹

记 Prior 输出为 `r`，Actor 经 WM 执行后的状态序列为 `s_hat`。建议把 Prior 目标拆开记录：

`J_prior = J_task_exec(s_hat, goal)`

`          + λ_ref * J_task_ref(r, goal)`

`          + λ_consistency * J_tracking(s_hat, r)`

`          + λ_smooth * J_smooth(r)`

`          + λ_feasible * J_feasible(s_hat, r)`

`          + λ_trust * J_trust(r, trusted_reference)`

这里的权重均待标定。增加 reference 任务项让“规划轨迹本身接近目标”成为显式要求；增加执行一致性项约束 reference 的可跟踪性。二者需要同时存在：只加一致性可能让 Prior 迎合尚不会运动的 Actor，退化成静止参考；只加 reference 任务项可能产生漂亮但无法执行的轨迹。

Prior 更新时仍冻结 Actor/WM 参数并保留输入梯度。关于一致性损失是否对执行侧 stop-gradient，应作为消融选择明确记录，不能无意中切断任务梯度。建议先完成固定参考下的 Actor 校准，再使用小权重一致性项逐渐启用 Prior 更新。

信任域的参考应来自已验证的状态/轨迹支持范围，不应无条件锚定原始 Prior 在分布外状态下的错误输出。可保留可信数据上的监督回放，限制后训练遗忘；目前 `supervised_weight` 占位项需真正实现后才有此效果。

Actor 继续以跟踪为主：L 加 root 速度跟踪，M 加 TCP 位置/速度跟踪，补充关节速度与必要的控制正则。不要依靠很弱的短时 root-position 项独自驱动前进。目标速度/TCP 均由 reference 一致计算，避免 Actor 与 Prior 同时追逐互相冲突的目标。

## 5. 重写过程与终点目标，先避免重复计权

建议明确采用：

`J_task = mean(cost_running[1:H-1]) + λ_terminal * cost_terminal[H]`

这个写法把过程和终点明确分开。不要保留当前等价于再加一次终点距离的 progress 项，再把它解释成独立过程奖励。若使用其他时间积分或折扣形式，应重新标定随 horizon 变化的尺度。

L 的过程项以速度/转向跟随为主，终点项关心末速度误差与是否仍有过大加速度；L 没有世界位置目标时，不必人为增加位置终点。

M 的过程项关心 TCP 距离、运动速度和必要的基座约束；终点项关心 TCP 距离，以及接近目标后降低末端速度。保持可采用平滑的近目标权重乘速度代价，并最终用真实的 0.5 s 成功保持验证。远离目标时不应强制末端静止，否则容易与 Reach 冲突。

各项先除以对应任务容差，再讨论权重；例如用速度容差归一化速度误差，用 Reach 距离容差归一化位置误差。初始可对比几组总过程/终点权重，但只将其作为实验候选，通过分任务梯度范数、方向和实际改善选择。

成功指示函数可用于评估、候选轨迹排序或终端价值学习。若后续引入 critic，需提供真实成功/失败轨迹与独立验证；不建议在数据和模型尚不可靠时再加入一个未验证的价值网络。

平滑项应包含当前真实速度作为边界条件，并比较相邻计划的重叠部分。底盘要求固定时，漂移约束应相对 episode 锚点，并将锚点上下文正确存入 Replay。

## 6. 用物理方向验证决定 WM 是否可以指导更新

单独保留按 episode 划分的数据，覆盖 L/M、动作幅度、策略阶段和 domain randomization；不能把从训练 Replay 再抽样的 NSE 叫 held-out 验证。

重点验证 `1/5/10-step` 的 root 速度、轮速、TCP 位置和末速度。对相同仿真初态与相同随机化参数施加 `a+εd`、`a−εd`，比较真实与 WM 的任务相关变化。接触切换处有限差分可能不稳定，需检查多个 ε，并区分局部平滑区与切换区，不能用一个 Jacobian 数字覆盖所有情况。

进一步的验收是：沿 WM 预测的下降方向做一个小的动作/策略改动，真实任务代价是否下降。预测精度与方向正确率都要按任务和状态区间统计。

在 10 步验证通过前不扩大 imagination horizon。通过后可对比 0.4/0.8 s 视野或终端价值，但必须同步增加数据覆盖和误差检查。较长 horizon 能表达更多到达/制动过程，也会放大模型偏差。

## 7. 混合任务与更接近 MPC 的后续选择

若要求严格一半环境执行 L、一半执行 M，固定环境 ID 分组，reset 时只更新组内命令。逻辑 batch32 可固定 L16/M16；当前 microbatch8 可每个固定 L4/M4，以维持任务均值和梯度累积的一致性。WM 也应检查任务采样比例及分任务误差。

当前 Prior 每 10 步规划并执行完整 10 步参考。WM/Actor 可靠后，可考虑每 1～2 步重规划，仅执行短前缀；这需要重新处理 reference phase、坐标重锚定、历史和跨计划连续性，不能只修改 cadence 配置值。

另一条可选路线是在训练阶段用可信 WM 对 Prior 生成的少量候选轨迹进行评分，或对 latent 做有限步优化，产生更好的规划目标，再蒸馏回 Prior。这样更接近“搜索后选优”的 MPC。但 learned WM 的误差可能被优化器利用，必须限制搜索范围并验证真实收益；在完成 A～C 之前不推荐实施。

## 8. 建议拆分的实现提交

1. 诊断与契约：修正 RMSE/门控标志/同任务命令敏感性；保存逐步快照与归一化统计。
2. 数据与 Prior v2：工作姿态、动作范围、归一化与数据意图修复；形成新的可复现 checkpoint。
3. Tracking 校准：固定可信参考，补充速度/TCP tracking，评估控制接口选择。
4. WM 校准：独立验证集、方向检查、合理样本利用率。
5. Prior 目标：过程/终点分离、reference 任务项、执行一致性、平滑边界与受限更新。
6. 混合实验：固定环境分组、分层 Replay，逐项消融后评估真实收益。

每一步保留前一版本 checkpoint 和评估结果。验收以真实任务改善为准，失败时应能定位是哪一层引入退化。
