# M1 V3.3 next-stage recommendations

## Current evidence

- **Motion Prior:** static high-carry references have direction-correct root displacement, but the fine-tuned Prior at it 3000 produces internally inconsistent live plans for forward ID `+0.12`: mean 0.2 s root displacement is weakly positive (`+0.0015 m`) while all four wheel references are negative. The mean four-wheel sign is wrong in 98% of plans and root/wheel sign disagreement in 94%. With the same Actor and all other conditions fixed, replacing trained Prior weights with `prior_initial` changes forward dx from `−0.090` to `+0.475 m`; stop drift changes from `−0.279` to `+0.077 m`. This is strong runtime evidence that Prior fine-tuning caused the forward and stop failures. The initial Prior is not a global replacement: at it 5000, a same-Actor swap fixes forward ID (`+0.809 m` versus `+0.126 m`) but breaks backward ID (`+0.018 m` versus `−0.242 m`).
- **Gradient path and actuator mapping:** Actor gradients are connected (runtime nonzero gradient norms and optimizer updates; it 3000 Actor tracks the wrong wheel reference at `0.141 rad/s` RMSE). Actor updates detach the Prior target by design; there is no direct Prior parameter gradient during Actor updates. The inverse action map passed physical wheel-direction/contact tests, so there is no evidence of a global sign/joint-order bug. At it 5000, initial-Prior swap improves forward task displacement despite worse wheel tracking RMSE (`0.705` vs `0.187 rad/s`), confirming that tracking loss does not rank real task quality.
- **World Model:** replay NSE1/8 improved from `0.0015/0.0063` at it 3000 to `0.00036/0.00120` at it 5000. Yet the same static Prior-derived action-response audit changed from predicting positive displacement for `−0.08/0/+0.12` at it 3000 to predicting negative displacement for all three at it 5000. It remains wrong on reverse/stop/forward sign response despite its lower replay error; action gradients are not trustworthy for optimizing Prior references.
- **Actor-only outcome:** at it 5000 with trained Prior, forward ID recovered from `−0.090 m` at it 3000 to `+0.126 m`, but positive-command reverse fraction remained `0.330`; stop drift was `−0.115 m`, backward ID overshot to `−0.242 m`, and yaw-only error was `0.19 rad/s`. No falls were observed. This is partial compensation, not task readiness.
- **Dataset dynamics feasibility:** V3.3 L passes the audit's URDF, SDK and joint-velocity screens, but most L motions are quick-screen / partial collision checks and no full dynamics validation is claimed. M has 88 hard/SDK position and 2,351 velocity-violating joint frames.

## Next work

1. Preserve the initial V3.3 Prior, the it 3000 Checkpoint, the it 5000 Checkpoint and their `prior_initial` weights. These are needed to reproduce the same-Actor Prior-swap comparisons.
2. Do not continue joint Prior optimization through the current WM. First add a task-specific held-out action-response set using the exact saved v3 inverse contract; measure 1/5/10-step signed body velocity and displacement for stop, forward and reverse. Require this check to pass before enabling Prior updates.
3. Retrain or calibrate Prior command conditioning on paired root and wheel outcomes so the two reference channels remain physically consistent across the evolving history distribution. In particular fix the `+0.12` forward references and the `−0.06` over-response; do not globally restore `prior_initial` as a complete solution because its it 5000 backward command also fails.
4. Add Actor objective telemetry that separates root, wheel, leg and arm reference tracking from task velocity. The it 5000 prior swap shows task performance improved while wheel tracking worsened, so task quality needs a direct measured gate.
5. Expand WM data/validation to cover the action support used by inverse Prior references, including forward/stop/reverse counterfactuals and recurrent states. Replay NSE alone is insufficient; monitor sign accuracy and command-conditioned slope.
6. Once target and WM checks pass, train a controlled actor-only or joint ablation with held-out fixed-seed evaluation. Keep ±0.3 m/s and `0.2 rad/s` yaw marked OOD. A run with the trained Prior at it 5000 was stopped at the user's request after approximately 86.8 minutes cumulative training; the latest complete checkpoint remains it 5000.
7. Keep action safety envelopes fixed to V3.3∩URDF∩SDK limits. All current fixed-eval groups had zero falls and zero action saturation, so widening physical limits is not indicated.

Any comparison with older v2 runs must disclose the different Prior, Reset and Action Contract, evaluation seed/command set and metric formula; it is not a causal ablation. The stopped run did not meet the originally planned two-hour duration because the user redirected the remaining effort to diagnosis; do not describe it as a completed two-hour training run.
