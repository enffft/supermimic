# Go2W 十小时训练准备与验证

开发分支为 `experiment/go2w-motion-prior`，起始提交 `e37cab38cddc493441fb5c75ab40e62ce7a08e7d`。历史模型来自 `08f61581c93d9e2337fdc18f3053823cb7ed577d`。本报告所在的提交包含本轮实现，实际运行记录 Git SHA、配置与 Motion Bank SHA-256。十小时实验由用户启动。本轮最大训练预算为单次 25 迭代的小规模 smoke 或 4096 环境的有限短测。

此报告记录首次准备短测及当时的晋级门槛。当前晋级配置、4 小时混合地形上限与 checkpoint 保存周期见主文档。 [当前训练手册](../../go2w_motion_prior.md)

## 实现与证据

| 原问题 | 实现 | 验证 |
|---|---|---|
| WM 冷启动从随机策略获得的参考邻域覆盖不足 | `motion_prior.py` 和 `motion_prior.yaml` 按并发配额分派 RSI、8/16 步参考状态附近的 Actor 探索和普通 Actor | 4096 正式入口短测累计采集比例约 40.4% 普通 Actor、9.9% RSI Actor、0% PD、49.7% 短程 Actor |
| 长时间末帧保持 | `manager_terms.py` 在参考片段结束时触发 timeout，并保存实际终点 | 128 集成测试见到参考 timeout 且无物理跌倒标记。4096 正式入口短测记录 10,768 次参考结束，观测到的超出末帧比例为 0 |
| 相位可将精确命令替换为低速命令 | `motion_prior.py` 先选择命令，再在选定 clip 内匹配启动、恒速或停止相位 | 对精确侧移命令给入另一速度的状态，仍选择精确命令。测试核对第一步对应下一帧、H8 连续窗口以及无覆盖命令回退 |
| 混淆平地技能等级与地形等级 | `manager_terms.py` 和 `curriculum.py` 保留独立的等级、技能与复习标签。普通 Actor 单轴按真实速度和方向推进等级 | 课程、集成与已有地形回归测试。参考来源窗口无自主成功标记 |
| 运动阶段切换不明确 | `training_stages.py` 和训练入口按评测迭代去重、淡出参考并按阶段分别选择 best | 受控连续评测触发两次切换。真实 MuJoCo 测试验证定时 resample 两次均修改 target ID、地形重分配和 Replay 边界、楼梯正向命令以及阶段恢复 |
| 短窗跟踪容易误判成完整技能 | `learner.py`、`replay.py` 和 `history.py` 将普通 Actor 完成的成功命令关联到同一 episode 和 target 的真实历史，按方向及速度分箱 | 测试检查 H8 步数、target ID、来源一致和自动 reset 边界，以及普通与保护池的事实来源 |
| 平地边界误判 | `evaluate_go2w_motion_prior.py` 加入 4 秒固定速度窗口和 2 秒命令切换段，区分物理跌倒、超时、提前碰边和完成 | 旧 last 的 0.30 m/s 前进从历史 0/3 修正为新协议 3/3，三次均完成整窗，vx RMSE 为 0.063–0.065 m/s |

普通平地划分 10 档，起始 vx、vy、wz 上限分别为 `[-0.15, 0.25]`、`[-0.10, 0.10]`、`[-0.20, 0.20]`，最终为 `[-0.35, 0.75]`、`[-0.35, 0.35]`、`[-0.80, 0.80]`。平地采样早期站立、纵向、侧移、旋转及耦合配额为 10/25/30/25/10%，后期为 5/20/25/20/30%。连续命令活动轴初始速度下限为 0.10 m/s、0.05 m/s 和 0.10 rad/s。平地跟踪升级要求至少 100 步、正确方向、足够的实际运动量、无跌倒，平均误差及 RMSE 在绝对下限与目标 35% 的较大值内。平移绝对下限为 0.05 m/s，旋转为 0.10 rad/s。前沿两次成功升级，三次失败降级，复习不推进前沿。

Stage 1 的独立基础评测分别检查站立、前后、左右、正反转，阈值为 90/80/80/60/60/70/70%，跌倒率上限 15%。站立 3 次，六个非静止方向各 6 次，对应至少通过 3、5、5、4、4、5、5 次。每 900 秒评测基础速度，每 1800 秒另有完整平地和切换结果。Stage 2 完整评测阈值为 95/90/90/80/80/80/80%，耦合 70%，切换 75%，跌倒率上限 8%，要求参考淡出完成并连续两次达标。平均值由固定试验的实际通过数计算。Stage 3 初始分配为平地 60%、崎岖 15%、上坡 7%、下坡 8%、单台阶上/下各 3%、连续楼梯上/下各 2%。后续地形配比和平地 imagination 40% 配额由配置记录。

## WM 与 Actor 梯度

`env.step()` 的 transition hook 在 autoreset 前捕获物理后继状态和实际执行 Action。Replay 输入、WM 动力学 normalizer 和预测监督沿用同一个 transition；Motion Bank 的训练侧调用限于 reset、参考动作候选和 Actor imagination Loss。独立集成测试逐元素核对 `s1` 与终止前物理状态、Replay Action 与混合 PD 实际输入。Actor 更新后 Actor 参数变化，WM 参数逐元素相等。

128 环境短测的首个 Actor 梯度诊断中，任务 Reward、Critic bootstrap 与 Motion Prior 梯度范数分别为 20.41、22.23、8.05。先验范数约为任务合成梯度的 41.1%。Reward 与先验余弦为 0.950，Critic 与先验为 −0.547，Reward 与 Critic 为 −0.580。左右侧移先验范数为 7.63/5.18，正反旋转为 5.76/6.86，动作饱和率为 0%。诊断仅为单个早期批次，保留原 Critic warmup 和 H8 设置，正式训练每 250 次 Actor 更新记录梯度。

## 性能与测试

后端为 `unisim.backend.mujoco.backend.MuJoCoBackend`，20 个原生 CPU 线程，RTX 4070 SUPER 运行 CUDA Learner。吞吐仅计训练循环，排除初始 64 步预采集。每轮用正式更新配额 10 次 WM、20 次 Critic、1 次 Actor，性能 smoke 将 WM-only 缩至 3 次迭代以覆盖 Actor。正式默认 250 次 WM-only。

| 短测 | 循环 transitions/s | s/iteration | CUDA 峰值 allocated MiB |
|---|---:|---:|---:|
| 2048 环境，profiling | 5487 | 0.933 | 2902 |
| 4096 环境，profiling | 8640 | 1.185 | 4109 |
| 4096 环境，profiling、关闭模仿 Loss，保留采集 | 8654 | 1.183 | 4098 |
| 4096 环境，无同步 profiling | 8370 | 1.223 | 4141 |
| 4096 正式入口的 WM-only 短测 | 8968 | 1.142 | 3829 |

4096 profiling 最后一个迭代含 3 个并行控制步，仿真 591 ms、WM 575 ms（含采样约 36 ms）、Actor 65 ms（含先验 Loss 约 0.51 ms）、Critic 16 ms、参考匹配 1.43 ms、参考采集约 2.04 ms。同比约为 47%、45%、5% 和 1% 的迭代时间。连续 PD 关闭时参考采集依然执行来源分派、时间相关探索、起止检查和物理记录。短测整机开销差异与测量波动相当，正式配置关闭同步 profiling。正式入口末次样本 GPU 利用率为 86%，进程 CPU 为 695%（按 CPU 核累加）。4096 profiling 峰值 CUDA 预留约 4188 MiB，进程 CPU RSS 峰值约 2595 MiB。

- 49 个 pytest 测试通过，1 个默认标记慢测试未运行。覆盖精确参考与阶段、真实动作与终点、H8 连续性、优化器训练链路、地形和 checkpoint。
- 128 环境 25 迭代完成 250 次 WM、22 次 Actor、440 次 Critic 更新。4096 环境完整更新 smoke 完成 160 次 WM、13 次 Actor、260 次 Critic 更新。有限损失和梯度进入日志。
- 4096 正式入口和预算停止已实测，生成独立外部 MuJoCo 评测、`best.pt` 与 2.6 GiB `last.pt`。同 profile 恢复短测从第 6 次迭代续至第 8 次。环境使用批量 reset 恢复，模型、Replay、normalizer 与优化器状态加载。
